# token-tollgate — 프로젝트 설명서

> AI 도구와 에이전트가 쓰는 LLM 호출을 한곳으로 모아, **작업별 비용을 보고, 예산을 넘지 않게 막고, 공급처 장애에도 멈추지 않게** 하는 개인·소규모 팀용 LLM 게이트웨이.
> 작업 이름은 `token-tollgate`다(짧게 부를 때는 tollgate). 이 문서는 공개 저장소에 들어가는 설계 기준 문서다.

## 1. 해결하려는 문제

AI 코딩 에이전트, 스크립트, 채팅 도구를 함께 쓰면 다음 문제가 생긴다.

1. 공급처(OpenAI, Anthropic, 로컬 모델)마다 키와 설정이 흩어진다.
2. 비용이 어느 프로젝트·작업에서 나가는지 알기 어렵다.
3. 에이전트가 반복 호출로 폭주하면 비용이 갑자기 늘어난다.
4. 공급처 장애나 속도 제한에 걸리면 작업이 멈춘다.

token-tollgate는 기존 도구가 **base URL만 바꿔** 연결할 수 있는 호환 API를 제공하고, 지나가는 모든 호출의 사용량과 비용을 기록·제한·전환한다.

## 2. 사용자와 대표 시나리오

- **사용자:** AI 도구를 여러 개 쓰는 개발자, 같은 조직 계정을 쓰는 작은 팀
- **시나리오**
  1. 프로젝트마다 가상 키를 만들고, 각 도구의 base URL과 키를 token-tollgate로 바꾼다.
  2. 대시보드에서 날짜·프로젝트·작업·모델별 토큰과 비용을 본다.
  3. 프로젝트 예산을 정해 두면, 예산을 넘는 호출은 실행 전에 거절된다.
  4. 한 공급처가 실패하면 규칙에 따라 다른 공급처로 넘어간다.
  5. 이 프로젝트를 AI 코딩 에이전트로 만드는 비용도 token-tollgate로 측정한다(자기 측정).

## 3. 범위

### 하는 것 (단계별)

**1단계 — 바로 쓸 수 있는 최소 기능**
- OpenAI 호환 `POST /v1/chat/completions` (일반·SSE 스트리밍)
- Anthropic 호환 `POST /v1/messages` (일반·SSE 스트리밍)
- 상류 공급처: OpenAI, Anthropic, OpenAI 호환 엔드포인트(로컬 Ollama 등), **시험용 가짜 공급처**(지연·오류·토큰 사용량을 설정으로 흉내)
- 1단계에서는 **같은 프로토콜끼리만** 중계한다(OpenAI 형식 요청 → OpenAI 호환 상류, Anthropic 형식 → Anthropic 상류). 형식 변환은 3단계.
- 가상 키: 발급·폐기, 해시로 저장, 키 = 프로젝트. 선택 헤더로 작업 태그(예: `X-Tollgate-Tag`)
- 요청마다 사용량 기록: 키·프로젝트·태그·공급처·모델·입력/출력 토큰·비용·첫 토큰까지 시간·전체 시간·상태·스트림 여부·오류 종류
- 요금표: 모델별 입력·출력 단가(100만 토큰당)를 설정이나 DB로 관리. **가격을 코드에 박지 않는다.**
- React 대시보드: 키 관리, 기간별 비용·토큰 요약, 프로젝트·모델·태그별 분해, 최근 요청 목록
- docker-compose로 한 번에 실행, 연결 방법을 담은 README

**2단계 — 돈과 정합성**
- 프로젝트 예산(선불 크레딧): 충전, 호출 전 **예약**, 응답 후 **확정**, 남은 금액 **해제**
- 스트림이 중간에 끊긴 경우의 정산 규칙(받은 만큼 확정, 공급처가 사용량을 주지 않으면 추정치로 표시)
- 추가만 하는 원장(충전·예약·확정·해제·조정). 잔액은 원장에서 계산, 음수 가용 잔액 금지
- 멱등 키로 같은 요청이 두 번 정산되지 않게 함
- 사용량 이벤트: 트랜잭션 아웃박스 → RabbitMQ 발행 → 소비자 집계 (재전달에도 중복 반영 없음)
- 정산 점검 작업: 내부 원장과 기록된 공급처 사용량을 날짜 단위로 대조하고 차이를 보고
- 동시성 테스트: 같은 예산에 병렬 요청이 몰려도 초과 차감이 없음을 증명

**3단계 — 안정성과 라우팅**
- 공급처 장애·시간 초과 시 폴백(스트리밍은 **첫 토큰 전**에만 전환), 서킷 브레이커
- Redis 기반 레이트리밋(키별·프로젝트별, 원자적 처리)
- 에이전트 폭주 차단(분당 비용·요청 수 한도)
- 라우팅 규칙: 태그·비용·지연시간 기준 공급처·모델 선택, OpenAI↔Anthropic 형식 변환
- Prometheus 지표, Grafana 대시보드(공급처별 지연시간, 폴백·거절 수, 비용)
- 부하·장애 주입 시험과 결과 보고서(가짜 공급처 사용, 직접 잰 수치와 조건만 기록)

**4단계 — 운영**
- k3s 등 경량 Kubernetes 배포 매니페스트, ArgoCD로 배포 관리
- 몇 주 실제 사용 후 지표 기반 회고와 기능 제안 문서

### 하지 않는 것
- 요청·응답 **본문 저장** (기본값). 기록은 메타데이터와 수치만
- 콘텐츠 검사, 개인정보 마스킹, 프롬프트 보안 필터 (범위 밖)
- 여러 사람이 하나의 공급처 키를 나눠 쓰게 하는 재판매·공유 서비스
- 결제 대행사(PG) 실제 결제 연동 (크레딧은 관리자가 충전)

## 4. 기술

| 영역 | 선택 | 메모 |
|---|---|---|
| 서버 | Kotlin, Spring Boot(WebFlux), 코루틴 | JDK LTS 21 이상. 버전은 시작 시 공식 출처에서 최신 안정판 확인 |
| 상류 호출 | Spring WebClient(스트리밍) | SSE를 받아 그대로 내보내며 사용량 이벤트를 파싱 |
| DB | PostgreSQL, R2DBC | 마이그레이션은 Flyway |
| 캐시·제한 | Redis (Lettuce) | 3단계 레이트리밋 |
| 메시징 | RabbitMQ (Spring AMQP) | 2단계 사용량 이벤트 |
| 프런트엔드 | React, TypeScript, Vite | 차트 라이브러리는 1단계 계획에서 결정 |
| 관측 | Micrometer, Prometheus, Grafana | 3단계 |
| 테스트 | JUnit 5, Testcontainers, 가짜 공급처 | 부하 시험은 k6 또는 JMeter |
| 배포 | Docker, docker-compose → k3s + ArgoCD | 4단계 |

## 5. 프로토콜 기준 (구현 전 공식 문서로 다시 확인)

- **OpenAI Chat Completions 스트리밍:** `data: {json}` 줄이 이어지고 `data: [DONE]`으로 끝난다. 요청에 `stream_options.include_usage=true`를 주면 마지막 조각에 `usage`가 온다. 게이트웨이는 클라이언트가 요청하지 않았더라도 사용량 집계를 위해 이 옵션을 상류에 붙이고, 클라이언트가 원하지 않은 사용량 조각은 응답에서 걸러 낸다.
- **Anthropic Messages 스트리밍:** `message_start`(입력 토큰), `content_block_*`, `message_delta`(출력 토큰 누적), `message_stop`, `ping`, `error` 이벤트. 인증은 `x-api-key`와 `anthropic-version` 헤더.
- 공급처 키는 환경 변수나 비밀 저장소에서만 읽고, 로그·응답·DB에 남기지 않는다.

## 6. 품질 기준

- 기능마다 테스트: 비용 계산, SSE 파싱·중계, 사용량 기록, 오류 처리, (2단계) 정산·동시성
- 실제 키 없이 전체 테스트가 돈다(가짜 공급처, Testcontainers)
- 수치는 직접 잰 값만 문서에 쓰고 측정 조건(환경, 요청 수, 동시성)을 함께 적는다
- 모든 단계 끝에 README의 실행·연결 방법이 실제로 동작하는지 확인

## 7. 1단계 완료 기준

1. `docker compose up` 한 번으로 서버·DB·대시보드·가짜 공급처가 뜬다.
2. `curl`로 OpenAI 형식과 Anthropic 형식 요청을 각각 일반·스트리밍으로 보내면 응답이 오고, 요청마다 사용량과 비용이 기록된다.
3. 실제 도구 하나(로컬 Ollama 또는 OpenAI 호환 클라이언트)를 base URL만 바꿔 연결해 기록이 쌓이는 것을 확인했다.
4. 대시보드에서 키 발급·폐기, 기간·프로젝트·모델·태그별 비용을 볼 수 있다.
5. 테스트가 모두 통과하고, `docs/dev-log/`에 작업 기록이 있다.

## 8. 개발 방식 (AI 코딩 에이전트 루프)

이 프로젝트는 AI 코딩 에이전트에게 작업을 맡기고 사람이 검증하는 방식으로 만든다.

1. **작업 명세:** 작은 단위로 목표·완료 기준·검증 방법을 정한다.
2. **구현:** 에이전트가 구현하고 테스트를 함께 작성한다.
3. **검증:** 테스트 실행 결과, 직접 호출 결과, 코드 검토로 확인한다.
4. **기록:** `docs/dev-log/NNN-작업명.md`에 명세·결정·검증 결과·남은 문제를 남긴다.

2단계부터는 개발에 쓰는 에이전트 호출을 가능하면 token-tollgate로 보내, 기능별 개발 비용을 대시보드로 확인한다.
