# 013 대시보드 디자인 시스템 교체와 개요 화면 재구성

- 명세 작성·승인·구현·검증: 2026-11-09
- 선행: 009·010(대시보드 화면과 단일 스타일시트), 011(nginx가 빌드 산출물을 서빙)
- 성격: 1단계를 닫은 뒤의 화면 손질이다. 2단계 계획과는 별개의 작업 단위이고 서버·관리 API·테스트 파일은 바꾸지 않는다

## 목표

개요 화면은 "같은 크기 카드 네 장, 차트, 표"라는 흔한 배치라 이 도구의 주인공인 비용이 다른 수치와 같은 무게로 읽혔다. Hallmark 디자인 스킬(v2.0.0)의 redesign 절차로 두 가지를 한다. 하나는 색·글꼴·간격·컨트롤을 토큰 체계로 바꾸는 것(시스템), 다른 하나는 개요 화면의 배치를 다시 짜는 것(구성)이다. 문구, 링크, 필터, 요청 목록으로 넘어가는 동작, 테스트가 읽는 구조는 그대로 둔다.

## 완료 기준

1. 개요에서 기간 총 비용이 화면의 가장 큰 숫자이고, 보조 수치 셋은 실선으로 나눈 줄, 일별 추이는 한 계열 선, 비용 내역은 상자 없는 전폭 표다.
2. 색·글꼴·간격은 `tokens.css`의 토큰만 거친다. 밝은·어두운 두 모드 모두 글자 대비 4.5:1, 포커스 링과 입력란 테두리 3:1을 넘는다.
3. 테스트 파일을 고치지 않고 28개가 그대로 통과한다. `npm run lint`, `npm run build` 통과.
4. Hallmark 정적 검사에서 대상 파일의 필수 위반(Floor)이 0이고, 바꾸기 전 기록과 대조해 빠진 링크·핸들러가 없다.
5. 다섯 화면(개요, 요청 목록, 키 관리, 요금표, 로그인)이 320~1920px에서 가로로 넘치지 않는다.
6. 번들과 이미지 크기를 전후로 재서 적는다.

## 명세 (2026-11-09 승인)

### 1. 범위

Hallmark의 redesign 기본 깊이(full)는 시스템과 구성을 함께 바꾼다. 이 대시보드의 시스템은 `dashboard/src/index.css` 한 파일의 전역 토큰이라 개요에만 적용할 수 없다. 토큰 파일이 들어오면 직접 쓴 간격·색이 모두 규칙 위반이 되므로 스타일시트 전체를 토큰으로 옮긴다. 그래서 개요는 배치까지 바꾸고, 요청 목록·키 관리·요금표·로그인은 배치와 마크업을 그대로 둔 채 겉모습만 새 시스템을 따른다.

## 결정과 이유

- **Cobalt를 골랐다.** 차가운 흰 바탕, 실선 표, 기계 값은 고정폭, 코발트 신호색 하나라는 재질이 표와 수치가 전부인 화면에 맞고, 지금까지의 요금소 파란색과 이어진다. Lumen은 소문자 영문 세리프 제목이 핵심인데 한글 제목에는 표현되지 않고, Coral은 종이 질감과 한 방향 그림자에 기대어 어두운 모드를 만들기 어렵다.
- **개요 배치는 "수치 옆 추이, 아래 장부"다.** 왼쪽 칸에 기간 총 비용을 가장 큰 숫자(`--text-figure`, 약 48px)로 두고 그 아래 요청 수·입력 토큰·출력 토큰을 실선으로 나눈 줄로 둔다. 세 수치는 비용의 구성 항목이 아니라 단위가 다른 보조 집계이므로 합산 관계처럼 보이게 꾸미지는 않았다. 오른쪽 칸은 일별 추이, 아래는 전폭 비용 내역 표다. 카드 네 장은 네 수치를 같은 무게로 만들었고, 이 도구에서 먼저 읽을 것은 비용이다. 60rem 아래에서는 한 칸으로 쌓이고, 40~60rem에서는 총 비용 옆에 보조 수치 셋이 온다.
- **표면은 세 단으로 나눴다.** 수치는 여백과 실선, 차트는 모서리를 깎은 실선 패널 하나, 비용 내역은 상자 없는 표다. 바탕(`paper`)과 패널이 같은 종이색이라 옅은 바탕 위 흰 카드가 없어졌다. 왼쪽 레일과 필터 줄만 한 단 어두운 중성색(`paper-2`)이다.
- **옅은 코발트 바탕은 "선택됨" 하나만 뜻한다.** 레일의 현재 화면, 고른 프로젝트, 선택 줄에서 고른 키가 같은 처리다. 처음에는 비용 비중이 가장 큰 행에도 이 바탕을 썼는데 선택된 행처럼 읽혀 뺐다(새 컨텍스트 리뷰 2). 순위는 정렬과 막대가 이미 말한다.
- **차트 선은 직선 구간이다.** 이전의 곡선(`monotone`)은 측정하지 않은 날짜 사이 값을 그려 넣었다. 하루 단위 합계는 점과 점을 곧게 잇는 것이 정직하다. 축 값은 측정값이라 고정폭으로, 격자는 화면의 실선색으로 맞췄다.
- **버튼은 키캡이다.** 테마의 3px 아랫변을 앱 밀도에 맞춰 40px 버튼은 2px, 32px 버튼과 선택 줄의 키는 1px로 줄였다. 채운 코발트 키는 화면의 주 동작 하나에만 쓴다. 선택 줄(기간, 지표, 내역 기준)은 가라앉은 받침 위의 키이고 고른 것은 눌린 상태다.
- **상태는 채운 칩이 아니라 글자색이다.** 활성·폐기·보관됨 배지는 말과 색을 함께 쓰되 배경과 테두리를 뺐다.
- **어두운 모드는 뒤집지 않고 다시 구했다.** 색상각은 그대로(250~262), 바탕 밝기 16.5%, 올라온 표면일수록 밝게, 강조색은 채도를 낮추고 밝기를 올렸다. 그림자는 끄고 모달은 실선 테두리로 구분한다. 강조색 버튼의 글자는 어두운 바탕색을 쓴다(밝은 글자는 4.5:1을 못 넘긴다).
- **한글은 단어 단위로 줄을 바꾼다**(`word-break: keep-all`). 설명 문장이 "브라/우저"처럼 끊기던 것을 막는다.
- **글꼴은 한 파일짜리 한글 부분집합으로 가져온다.** 조각 방식은 쓰는 글자만 받지만 `@font-face` 360개가 주 CSS에 들어가 CSS가 260 kB(gzip 110 kB)가 되고, 그 CSS는 첫 화면을 막는다. 한 파일 방식은 CSS가 27 kB로 남고 글꼴은 `font-display: swap`으로 따로 받는다. 로컬·사내망에서 쓰는 도구라 굵기 셋의 woff2 1.6 MB를 받아 두는 쪽을 택했다(측정값은 아래).
- **테스트가 단언하는 문구는 그대로 두었다.** "성공 10 · 실패 2"와 상태 줄의 가운뎃점은 한 줄에 점 하나인 캡션·상태라 스킬 규칙에서도 허용된다.
- **화면 캡처는 헤드리스 Chrome을 DevTools 프로토콜로 직접 몰아 찍었다.** 스킬의 렌더 계층은 로그인 화면을 넘지 못하므로, 세션 저장소에 예시 관리자 토큰(`.env.example`의 값)을 넣고 찍는 작은 스크립트를 작업용으로 썼다. 스크립트와 캡처는 저장소에 두지 않는다.
- **시스템을 `dashboard/design.md`로 잠갔다.** 나머지 세 화면을 나중에 손볼 때 같은 색·글꼴·컨트롤을 쓰고 배치만 달라지게 하기 위해서다.

## 겪은 문제

1. 모델 이름이 고정폭으로 나오지 않았다. `.btn-link`의 `font: inherit`가 앞서 선언한 `.mono`의 글꼴을 덮었다. `.btn-link.mono` 규칙을 뒤에 두었다.
2. 375px에서 요금표와 키 관리 화면의 문서 폭이 626px·579px로 잡혔다. 표 머리의 숨김 라벨(`.visually-hidden`, `position: absolute`)이 가로 스크롤 상자인 패널을 기준으로 잡히지 않아 상자 밖으로 문서 폭을 늘렸다. `.panel`과 `.table-scroll`에 `position: relative`를 주어 상자 안에 가뒀다.
3. 320px에서 필터 줄의 프로젝트 선택 상자가 화면을 11px 넘었다. 선택 상자는 가장 긴 옵션만큼 넓어지므로 `min-width: 0`과 줄어들 수 있는 flex 값을 주었다.
4. 한글 글꼴을 조각 CSS(`400.css`)로 가져오니 주 CSS가 260.32 kB(gzip 109.76 kB), 산출물이 559개 파일이 됐다. 한 파일 부분집합(`korean-400.css`)으로 바꿨다(결정과 이유).
5. 375px에서 차트 패널의 제목 "일별 추이"가 두 줄로 접혔다. 패널 머리를 `flex-wrap`으로 두어 컨트롤이 아랫줄로 내려가게 했다.
6. Hallmark 검사를 `src` 전체에 돌리면 손대지 않은 화면에서 필수 위반 3건이 나온다(남은 문제). 이번 대상(개요와 공용 파일, 스타일시트)만 돌리면 0건이다.

## 남은 문제

- 손대지 않은 화면에 스킬 기준 필수 위반이 3건 남아 있다. 요금표 표(`PriceTable.tsx`)와 요청 목록 표(`RequestTable.tsx`)의 빈 칸 "—" 두 곳, 요청 목록 표 머리의 "토큰 (입력 · 캐시 · 출력)". 이번 범위는 개요의 구성이라 다른 화면의 문구와 마크업은 그대로 두었다. 그 화면들을 손볼 때 함께 정한다.
- 요청 목록·키 관리·요금표는 겉모습만 바뀌었고 배치는 010·009 그대로다. 키 관리 화면에는 채운 주 버튼이 둘("추가", "키 발급")이고, 몇 곳에 인라인 글자 크기(`fontSize: 13`)가 남아 있다.
- 불러오는 중 상태는 여전히 글자("불러오는 중…")다. 차트 자리는 높이를 잡아 두었지만 올 내용 모양의 뼈대 화면은 그리지 않았다.
- 좁은 화면에서 표는 가로로 스크롤한다. 개요의 비용 내역은 첫 열을 고정했고, 다른 화면의 표(요청 목록, 키, 요금표)는 그대로다.
- 30일 보기의 차트가 이전 전폭 배치보다 좁다. 기간이 길 때만 차트를 전폭으로 바꾸는 방법이 있지만 배치가 기간에 따라 달라지므로 넣지 않았다.
- 어두운 모드에서 본문 굵기를 한 단 낮추는 처리(400 → 350)는 하지 않았다. 싣는 굵기가 400·500·600뿐이다.
- 모드는 OS 설정을 따른다. 화면에서 바꾸는 스위치는 없다(토큰은 `[data-mode="dark"]`로도 걸리게 해 두었다).
- 한글 글꼴은 굵기마다 전체 부분집합 한 파일이다. 쓰는 글자만 추리거나 woff를 빼면 산출물이 줄지만 빌드 단계가 하나 더 생긴다.
